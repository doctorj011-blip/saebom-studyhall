# 새봄 면학관 앱 — 배포 설명서

새봄 면학관 운영 시스템은 스마트폰 홈 화면에 앱으로 설치해서 쓰는 **웹앱(PWA)** 3종으로 구성됩니다.
모든 앱은 하나의 GitHub Pages 주소에서 배포되며, 공통 Firebase(`saebom-studyhall`)로 실시간 연동됩니다.

---

## 1. 앱 구성 & 접속 주소

배포 기본 주소: `https://doctorj011-blip.github.io/saebom-studyhall/`

| 앱 | 대상 | 주소 |
|----|------|------|
| 🧑‍🎓 **학생 앱** | 학생 | `.../saebom_student.html` |
| 👪 **학부모 앱** | 학부모 | `.../saebom_parent.html` |
| 🖥️ **관리자·키오스크 앱** | 운영자 / 입구 키오스크 | `.../saebom_schedule_with_hours.html` |

- **로그인**: 세 앱 모두 **휴대폰 번호 뒷 4자리**로 로그인합니다. (등록된 번호 기준)
- **키오스크 모드**: 관리자 앱 주소 뒤에 `#kiosk` 를 붙이면(`...saebom_schedule_with_hours.html#kiosk`) 입퇴실 전용 키오스크 화면으로 자동 실행됩니다.

## 3. 배포 / 업데이트 방법 (GitHub Pages)

앱을 수정한 뒤 아래 방법 중 하나로 올리면 몇 분 내 자동 반영됩니다.

**방법 A — 파일 교체 후 업로드 (간단)**
1. GitHub 저장소(`doctorj011-blip/saebom-studyhall`) 접속
2. 바꾼 HTML 파일을 끌어다 놓아 업로드(덮어쓰기) → **Commit**
3. 2~5분 후 배포 주소에서 새 버전 확인

**방법 B — Git 사용**
```bash
cd C:\Users\docto\saebom-studyhall
# 최신 HTML을 이 폴더로 복사한 뒤
git add -A
git commit -m "update apps"
git push
```

> ⚠️ **캐시 주의**: 학생·학부모가 이미 설치했다면, 업데이트가 바로 안 보일 수 있습니다.
> 앱을 완전히 닫았다 다시 열거나, 브라우저에서 새로고침하면 최신 버전으로 갱신됩니다.

> ℹ️ 최초 1회 설정: 저장소 **Settings → Pages → Branch: `main` / `(root)` → Save**

## 4. 학생·학부모 휴대폰에 설치하기

주소를 문자/카톡으로 보내주고, 아래 기종별 안내대로 설치하게 하세요.

### 📱 갤럭시 — 삼성 인터넷(기본 브라우저)
1. 주소를 **삼성 인터넷**으로 접속
2. 화면 **우측(하단)의 점 세 개 `⋮`** 메뉴를 탭
3. **`설치 및 바로가기`** 항목 선택
4. **설치** → 홈 화면에 앱 아이콘 생성 완료 ✅

### 📱 갤럭시/안드로이드 — Chrome
1. 주소를 **Chrome**으로 접속
2. 하단 **"앱 설치"** 배너를 탭
   - 배너가 없으면 우측 상단 **`⋮` → `앱 설치`**(또는 `홈 화면에 추가`)
3. 홈 화면에 앱 아이콘 생성 완료 ✅

### 🍎 아이폰 — Safari
1. 주소를 **Safari**로 접속 (Chrome 아님)
2. 하단 **공유 버튼 `□↑`** 탭
3. **`홈 화면에 추가`** 선택 → **추가**
4. 홈 화면에 앱 아이콘 생성 완료 ✅

> 설치하면 주소창 없이 전체화면 앱처럼 실행됩니다. 로그인은 **휴대폰 번호 뒷 4자리**.

## 5. 관리자 참고

- **관리자 앱 설치**: 위 학생 앱과 동일한 방법으로 관리자 앱 주소를 설치하면 됩니다.
- **키오스크(입구 태블릿/PC)**: 관리자 앱 주소 `#kiosk` 로 실행. 전화 뒷 4자리 입퇴실, 자동문 릴레이(Web Serial), 알림톡 발송 지원.
- **데이터 연동**: 학생 앱에서 저장한 스케줄(참여 `O` / 불참 `X`(사유) / 중간입실 `세모`(입실시간))은 Firebase를 통해 관리자 앱 시간표에 실시간 반영됩니다.
- **카톡 링크 미리보기**: 학생/학부모 앱 주소를 카톡에 붙여넣으면 자동으로 이미지가 있는 미리보기 카드가 뜹니다(Open Graph 태그, `icons/og-student.png` / `icons/og-parent.png`). 이미지를 따로 첨부할 필요 없이 주소만 보내면 됩니다.

## 6. 🔒 Firestore 보안 규칙 관리 (중요)

**2026-07-14 부로, Firestore 보안 규칙의 "원본"은 이 저장소의 `firestore.rules` 파일입니다.**
그 전까지는 Firebase 콘솔에서 직접 관리했지만, 이제 파일 → 배포 방식으로 코드처럼 관리합니다.

### 규칙을 바꿀 때 (항상 이 순서)

1. **`firestore.rules` 파일을 수정** (콘솔에서 직접 고치지 말 것 — 다음 배포 때 덮어써집니다)
2. 파일 상단 **`[배포 이력]`에 날짜·변경 요약** 한 줄 추가
3. 배포:
   ```bash
   bash scripts/deploy-rules.sh          # 변경분 보여주고 확인 후 배포 (권장)
   # 또는
   firebase deploy --only firestore:rules
   ```
4. 변경한 `firestore.rules`를 **git commit / push** (콘솔과 저장소가 항상 일치하도록)

> ⚠️ **주의**: `firebase deploy --only firestore:rules` 는 콘솔 규칙을 **이 파일로 통째 교체**합니다.
> 그래서 규칙 수정은 반드시 이 파일에서만 하고, 콘솔에서 급히 고쳤다면 그 내용을 이 파일에도 반영한 뒤 커밋해 두세요.

### 자동 배포 (GitHub Actions)

`.github/workflows/deploy-firestore-rules.yml` 이 있어서, `firestore.rules` 를 고쳐 **`main` 에 push 하면 콘솔에 자동 배포**됩니다.
PR 에서는 **검증(dry-run)만** 돌아 잘못된 규칙이 머지 전에 걸러집니다. → 규칙이 바뀔 때마다 자동으로 확인·반영됩니다.

**최초 1회 시크릿 등록** (이거 없으면 워크플로가 실패):
1. Firebase 콘솔 → **프로젝트 설정 → 서비스 계정 → "새 비공개 키 생성"** → JSON 다운로드
2. GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret**
   - 이름: `FIREBASE_SERVICE_ACCOUNT`
   - 값: 위 JSON 파일 **전체 내용** 붙여넣기

> 이후로는 `firestore.rules` 만 고쳐 push 하면 끝. 로컬에서 직접 배포하려면 `bash scripts/deploy-rules.sh` 를 써도 됩니다(둘 다 같은 파일이 원본).

### 냉방(에어컨) 관련 컬렉션
`ac_config`(설정·zone 매핑) · `ac_commands`(수동 명령) · `ac_state`(상태, 서버만 쓰기) — 대시보드 냉방 패널이 사용합니다.

## 관리자 앱 회귀 검증

외부 패키지 설치 없이 Node.js로 실행합니다. 가상 입력과 모의 저장소만 사용하며 운영 Firebase에 접근하지 않습니다.

```bash
node --test tests/admin-regressions.cjs
```

격리된 화면 미리보기는 `node scripts/preview-admin.cjs` 실행 후 `http://127.0.0.1:8765/`에서 확인합니다. 앱 스크립트를 제거하고 가상 학생만 표시하며 Firebase 연결을 차단합니다. 실제 출결·문 제어 통합 테스트를 대신하지 않습니다.

### 2026-09-12 관리자 수정본

- `saebom_schedule_with_hours.html`과 새 `saebom-admin-core.js`를 함께 배포해야 합니다.
- 출결 저장 성공을 확인한 뒤 완료·문 열기·알림을 진행합니다. 네트워크 또는 권한 오류에서는 비원자 쓰기를 하지 않고 오류를 표시합니다. **오프라인 상태에서는 출결을 확정하지 않으므로 연결 복구 후 재시도가 필요합니다.**
- 오래된 로그 정리는 공부시간 원본인 `attendance_sessions`를 보존합니다.
- 앱 안내와 수납 계산은 설정된 기본요금을 공유합니다. 이미 생성된 월별 안내 금액은 재발행 시 덮어쓰지 않고 수납에서도 그대로 사용합니다. 기존 금액을 정정하는 별도 절차는 이번 변경에 포함되지 않습니다.
- 기본요금·할인·납부 조회가 실패하면 납부 처리와 미납 안내 발송을 중지합니다. 설정된 기본요금이 없으면 수납 탭에서 먼저 저장해야 합니다.
- 미래 퇴원 예정자를 해당 청구월 이용기간에 따라 포함합니다. 현재 명부에 있는 기존 청구·납부 대상도 보존합니다. 이미 명부에서 삭제된 학생의 과거 미납을 완전 복원하는 역사 명부는 별도 작업입니다.
- 방학 제외 교시를 현재 교시 표시와 배정 판단에 반영하고, 시간은 24시간제로 표시합니다.
- 미등록 입퇴실 화면의 문 제어를 숨깁니다. 수동 개방·자동개방 설정 변경에는 관리자 토큰을 서버에서 확인합니다. 이 UI 변경 자체가 Firestore 권한을 강화하는 것은 아닙니다.
- 현재 재실과 일별 이력을 분리하고 로딩·연결 오류를 0명과 구분합니다. 모바일 관리 탭과 기본 F5 새로고침을 복원합니다.

### 남은 구조 변경

동명이인 이름 구분자를 없애려면 이름을 참조하는 세션·외출·학생·학부모·서버 로직을 모두 UID로 이관해야 합니다. 이번 수정은 기존 이름 키와 중복 방지장치를 유지합니다. 전체 파일 분리도 계산 규칙 모듈 분리부터 시작했으며 나머지 기능의 지연 로딩은 별도 작업입니다.

저장소의 Firestore 규칙에는 명부·출결 등의 공개 읽기/쓰기 허용이 남아 있습니다. 배포 규칙이 저장소와 같은지는 확인하지 않았습니다. Firebase Auth 및 역할별 서버 검증을 먼저 도입한 뒤 규칙을 잠가야 하며, 규칙만 바로 잠그면 기존 세 앱과 키오스크가 중단될 수 있습니다. 이번 변경에서 규칙 배포와 운영 데이터 이관은 수행하지 않습니다.
